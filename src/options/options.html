How AidTune reads data

AidTune has no sign-in and no app registration of its own. It borrows the access tokens the Intune portal already holds for you, and only from tabs on intune.microsoft.com:

  1. It reads the Authorization header of the portal's own requests to graph.microsoft.com and *.manage.microsoft.com. Other tabs (Outlook, Teams, Graph Explorer …) are ignored.
  2. As a fallback it scans the portal's sessionStorage and localStorage for tokens. To find them it inspects every stored value; only unexpired tokens addressed to Graph or Intune are kept, all else is discarded immediately.

With those tokens it makes read-only requests to Microsoft: groups, memberships, assignments, connectors. Every request is a GET (Graph requests are grouped through its $batch endpoint, which contains only GETs). It never creates, changes or deletes anything — but because the tokens are yours, it can read whatever your account can.

Also read on the portal page: the URL fragment (to know which page you are on), the portal's colours (to match the theme) and the position of its left menu (to place AidTune's entry). Nothing else, and no other website.

Nothing leaves your browser except requests to Microsoft. Tokens are kept in memory only and are never written to disk. No analytics, no tracking, no server of ours. Full privacy policy.

Don't take our word for it — AidTune is open source, so audit the code yourself: github.com/1Oeee/FERMtools. Token handling is in src/background/token.js and src/content/token-scan.js.
